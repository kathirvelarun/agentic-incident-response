INC-2843 — Fraud model inference timeout
Draft
Generated by PostmortemAgent using incident chat, 23 alerts, Splunk logs, and Datadog metrics. Review before publishing.
Summary
The fraud scoring service experienced a complete outage for 47 minutes on Jun 11 starting at 09:12 UTC. A 2.3x traffic spike driven by a targeted marketing campaign exhausted GPU memory on model serving pods, causing inference requests to time out. All fraud-dependent transaction flows were affected, resulting in fallback to rule-based scoring with higher false-positive rates.
Timeline
09:08
Marketing campaign email blast sent
3.4M emails, 2.3x normal transaction rate
09:12
Fraud model pods GPU OOM
All 4 inference pods crashed simultaneously
09:13
AIR alert group created, P1 opened
L1 TriageAgent activated — no runbook match
09:18
On-call engineer identified GPU exhaustion
Scaled inference fleet from 4 → 8 GPU pods
09:59
Service fully recovered, MTTR 47m
All transactions reverting to ML scoring
Root cause
No HPA (Horizontal Pod Autoscaler) configured for the fraud inference deployment. GPU pods had a fixed replica count of 4 with no burst capacity. The marketing team did not notify SRE of the planned campaign, so no pre-scaling was done.
Action items
Configure HPA for fraud-inference: min 4, max 12 GPU pods
ML Platform teamDue Jun 15
Establish SRE notification process for marketing campaigns > 1M users
Engineering + MarketingDue Jun 18
Add L3 auto-scale runbook for GPU inference pods to AIR knowledge base
Platform SREDue Jun 20
Load test fraud-svc at 5x normal traffic to validate new HPA config
